# CLAUDE.md — Nedito

## What this project is

Nedito (formerly DeepDraw) is a browser-based diagramming application with full draw.io feature parity as the baseline, plus one flagship differentiator: **nested diagrams**. A nested node renders in its parent diagram as a compact box showing a live miniature of what is inside it — generated by default, overridable by the author (CLAUDE_HISTORY.md D43, which reversed the original "author-designed, nothing auto-generated" rule) — and opens into its own full canvas via zoom-in navigation with breadcrumbs. This feature is not an add-on; it is designed into the data model from day one.

Reference product for **behaviour and keyboard** decisions: draw.io (app.diagrams.net). When in doubt about how a feature should behave (selection, connection, editing, shortcuts), match draw.io's behavior unless this file says otherwise. **Visual layout and default styling are Nedito's own, not draw.io's** (Redesign, `docs/DeepDraw_Redesign_Spec_20261004_v1.0.md`; CLAUDE_HISTORY.md D90 supersedes the original layout-parity principle). We never copy draw.io code or branding; its repo ships minified sources and its maintainers state it is not suitable as a base for other products, so Nedito is a ground-up build.

Nedito itself is open source (Apache 2.0). Include LICENSE at repo root and a NOTICE file listing third-party icon set licenses and attributions. The `.nedito` format is open and documented.

**Asset and code provenance guardrail (hard rule):** never copy code, icon sets, stencil libraries, or diagram templates from the drawio repositories (jgraph/drawio, jgraph/drawio-desktop) or from app.diagrams.net, in any form, including converted, traced, or visually similar reproductions. Their stencil assets carry separate restrictive terms and third-party copyright chains. Approved stencil sources only: official Microsoft Azure architecture icons, official AWS architecture icons, official Google Cloud icons (each under their published usage terms), and openly licensed general shape sets (record license + source per section in NOTICE). General shapes we draw ourselves are original SVG. The name "draw.io" is a registered trademark: it may appear in docs only as a factual compatibility reference, never in UI branding, marketing that implies affiliation, or the product name.

## Non-goals (v1)

- No backend, no authentication, no user accounts, no server-side storage.
- No real-time collaboration.
- No cloud storage integrations (Drive, OneDrive) yet.
- Sharing = exporting a `.nedito` file and sending it by any means. Opening = drag-and-drop or file picker in Nedito.

## Brand indirection (rename-ready)

The product is **Nedito** (short for Nested Diagram Tool), served at **nedito.app**. It was called DeepDraw, at myconifer.app, until 2026-10-06 — renamed because another live product, deepdraw.app, writes `.deepdraw.json`, `.deepdraw.html` and `.deepdraw.png` files (CLAUDE_HISTORY.md D100). Keep building for a one-file rename:

- All identity lives in `src/app/brand.ts`: the `BRAND` object (`name`, `tagline`, `fileExt`, `formatId`, `storagePrefix`, `host`, `contact`), `APP_ORIGIN`, and `LEGACY_BRANDS` — every earlier identity, read forever and never written. Every UI string, document title, export dialog, file filter, localStorage key, link and host reads from there. Hardcoding the product name or a host anywhere else is a review-blocking defect; code identifiers stay brand-neutral (`DiagramDocument`, `documentFormat.ts`, `editablePngFormat.ts`), so a rename never touches them.
- CSS class prefixes, CSS custom properties and test ids use a neutral `nd-` prefix (was `dd-` until D100), not the full name.
- Rename policy for persisted data: after any rename, the app writes the new `formatId`/extension but reads all previous `formatId`s and extensions forever (`KNOWN_FORMAT_IDS` in `file/migrations/`, `OPENABLE_DOC_EXTS` in brand.ts; the Word export's embedded part likewise), and migrates old `storagePrefix` keys — and the Recent list's IndexedDB database — to the new prefix on first launch, keeping the originals until a later load confirms the copies (`app/storageMigration.ts`). No user file or autosave is ever orphaned by a rename.
- Hosts: links the app hands out (share links, the live link in a copied image) are built by `app/appOrigin.ts` on `APP_ORIGIN`. Every other host that serves the build — today only `www.nedito.app` (`ALIAS_HOSTS`) — redirects there in the app (`app/originGuard.ts`), keeping path and `#` fragment, unless that origin holds the visitor's own work, which is offered for download first. The old `myconifer.app` is no longer served (D106): old *files and storage* are read forever, old hosts are not.

## Core editor behaviors (Phase 1 parity checklist)

Implement these to draw.io fidelity. Each is a discrete work item; do not half-implement several at once.

- Select (click, shift-click, rubber band), move, resize with 8 handles, rotate. A selected shape is outlined along its own outline in the accent — a diamond as a diamond — with the resize handles at its box's corners; a trace's focus and Pulse follow the outline too (D130). Vendor icons and pictures keep a box.
- Connect: hover a shape shows a **＋ just outside the middle of each side** (R3, D92; draw.io shows arrows there) + corner perimeter connection points; drag from them creates an edge, and clicking a ＋ (or Alt+Shift+Arrow) adds a connected, default-styled copy on that side with its label open. Edge styles: straight, orthogonal, curved — **curved is the default** (deliberate departure from draw.io's orthogonal default, chosen 2026-08-20 as a visible differentiator). Arrowheads configurable both ends. Either end of an existing edge can be dragged onto a different shape rather than deleting and redrawing it.
- Edge waypoints: drag edge segments to add/adjust waypoints (orthogonal rerouting).
- Labels on shapes and edges (double-click to edit, inline rich text basics: bold, italic, font size, color, align). Edge labels drag along or off their line and keep that place relative to it (`DEdge.labelPosition`, D97); "Reset label position" puts one back.
- Copy/paste/duplicate (Ctrl+C/V/D), delete, undo/redo (Ctrl+Z/Y) — undo/redo must work **across nesting levels** (one history stack tagged with diagram scope).
- Group/ungroup (Ctrl+G / Ctrl+Shift+U). Note: a group is NOT a nested node; groups are flat draw.io-style groups.
- Z-order: to front / to back / forward / backward.
- Keyboard shortcuts: match draw.io's map (arrow keys nudge, Ctrl+Shift+H fit page, Ctrl+= / Ctrl+- zoom, F2 rename, etc.).
- Zoom 10%–400%, fit-to-content, Ctrl+scroll zoom, space-drag or middle-drag pan. The zoom bar carries a draggable slider for any value in that range alongside the +/- buttons, which stay on a clean 25% grid; zoom is remembered per diagram, nested levels included.
- Grid + snap, toggleable; alignment/distribution commands in Arrange.
- Multi-page documents (tabs along the bottom like draw.io). Pages are siblings; nesting is orthogonal to pages.
- Export: PNG (with scale/transparent options), SVG, and native `.nedito`; also an editable `.nedito.png`, PDF, print, PowerPoint (`.pptx`, Slide Zoom into nested blocks) and Word (`.docx`, carrying its own `.nedito` copy). Import: `.nedito` and the older `.deepdraw`, the editable PNG, the Word export, and draw.io XML (best-effort, D55, D112, D132–D137). **Animated image (.gif)** (G1, D131): the level as it moves on the canvas, every frame the SVG export at one moment of its motion, encoded in-repo, at 25 frames a second (D140); a still level makes a one-frame GIF. ## The nesting feature (flagship — build alongside Phase 1, never defer)

### Concepts

- A **nested node** lives in a parent diagram and references a **child diagram** by ID.
- **Collapsed view — auto-generated by default, author-overridable** (changed 2026-08-20; was "author-designed, nothing is auto-generated"): the compact box shows a live miniature rendered from the child diagram's actual contents, so it can never go stale or claim "Empty" over a diagram full of shapes. The author still owns it when they want to: setting `collapsed.icons` replaces the miniature with that chosen icon row, and `collapsed.summary` adds an optional subtitle. The nested node's **name** is its `label`, edited by double-clicking the box like any other node; renaming it renames the child diagram too, so the box and the breadcrumb never disagree. Double-click therefore does *not* open the child — the ⤢ button and the right-click menu do.
- **Ports**: named anchor points on the nested node's border. Each port maps to at most one node inside the child diagram. External edges attach to ports — every edge dropped on a nested node gets one, created automatically on the side it landed if the author didn't aim at an existing port dot. A port may be **unmapped** (`innerNodeId` absent) when the child has nothing to point at yet; that is a real state, surfaced inside the child as an amber "waiting to be linked" ghost with a draggable endpoint, never a silently dropped connection. Port dots render on the box (dashed amber while unmapped, solid once mapped); hovering shows the mapping.
- **Navigation**: opening a nested node zooms the viewport into it (animated scale + fade) and replaces the canvas with the child diagram, fitted to content. A breadcrumb trail shows the path (e.g., `Main › Payment Service › Fraud Engine`). Clicking any crumb or pressing Esc navigates back. Viewport state per level is remembered within a session.
- **Ghost links**: inside a child diagram, connections that cross the boundary render as dashed pills at the canvas edges ("⇠ API Gateway · parent" entering, "Orders DB · parent ⇢" leaving), attached to the mapped inner nodes. Ghosts are read-only from inside; the mapping is edited on the parent's port settings.
- **Recursion**: nesting depth is unlimited. Renderer must only mount the currently viewed diagram.
- **Creating a nested node**: (a) insert an empty nested node from the sidebar (General section, "Nested Block" shape), or (b) select existing shapes → right-click → "Convert to nested block" (moves selection into a new child diagram, creates the nested node in place, auto-creates ports for every edge that crossed the selection boundary, prompts the author to design the collapsed view).

### Data model (authoritative)

```typescript
// The document is a flat map of diagrams; nesting is by reference.
interface DiagramDocument {
  formatVersion: number;          // integer, bump on breaking changes
  meta: { title: string; created: string; modified: string; appVersion: string };
  rootDiagramIds: string[];       // one per page (multi-page)
  diagrams: Record<string, Diagram>;
}

interface Diagram {
  id: string;
  title: string;
  nodes: DNode[];
  edges: DEdge[];
}

type DNode = ShapeNode | NestedNode | GroupNode;

interface NodeBase {
  id: string;
  position: { x: number; y: number };
  size: { w: number; h: number };
  rotation?: number;
  z: number;
  style: StyleMap;                // fill, stroke, fontSize, etc. draw.io-like keys
  label?: RichLabel;
}

interface ShapeNode extends NodeBase {
  type: "shape";
  shapeRef: string;               // stencil id, e.g. "azure/vm", "flowchart/decision"
}

interface NestedNode extends NodeBase {
  type: "nested";
  childDiagramId: string;
  collapsed: {
    icons: string[];              // stencil ids for the mini icon row
    summary?: string;
  };
  ports: Port[];
}

interface Port {
  id: string;
  side: "top" | "right" | "bottom" | "left";
  offset: number;                 // 0..1 along the side
  innerNodeId?: string;           // node id within the child diagram; absent while unmapped (format v2)
  label?: string;
}

interface DEdge {
  id: string;
  source: EdgeEnd;                // { nodeId, portId? , anchor? }
  target: EdgeEnd;
  waypoints?: { x: number; y: number }[];
  style: StyleMap;                // edgeStyle: straight|orthogonal|curved, arrows, dash
  label?: RichLabel;
}
```

The block above is the core; the optional fields added since (layers, assets, page size and background, edge label position, motion and presentation, Nested Block `peek`) are in `src/model/types.ts` and documented per version in `docs/FORMAT.md`.

Invariants (enforce in a validation module, test heavily):
- Every `childDiagramId` exists in `diagrams`; no diagram is its own ancestor (no cycles).
- Every `port.innerNodeId`, when set, exists in the referenced child diagram; deleting an inner node a parent's link enters through prompts: keep the link waiting (its port unmapped, to relink later), or remove the port and the external edges attached to it (D138).
- Deleting a nested node that holds shapes prompts: delete its child diagram subtree, or keep its contents — lifted onto this level where the block was, links through mapped ports re-attached to the shapes they led to (D138; replaces the original "unused pool", which had nowhere to be seen). One undo entry either way.
- IDs are nanoid strings, unique across the whole document.

## `.nedito` file format (open format)

Purpose: portable, open, human-readable single-file format, the same philosophy as `.drawio` XML. Nedito is people's first choice to open it because only Nedito understands nesting, not because the file is locked.

- Content: the `DiagramDocument` as pretty-printed UTF-8 JSON. First keys are `"format": "nedito"` (`"deepdraw"` before D100, still read) and `"formatVersion": <int>` so the file self-identifies.
- On open: check `format` and `formatVersion` (≤ app's supported version, else show upgrade message), validate against the model invariants, then load. Reject failures with a clear error, never a crash.
- Diff-friendly: stable key ordering and pretty printing so `.nedito` files diff cleanly in Git.
- Extension `.nedito` (`.deepdraw` before D100, still opened); open via file picker and drag-and-drop onto the app window.
- Publish the format: keep `docs/FORMAT.md` in the repo describing the schema per version, updated with every `formatVersion` bump.
- `.nedito.png` export (PNG with the JSON embedded in a metadata chunk, like draw.io's editable PNG), so a shared image is also the editable file; `.deepdraw.png` files from before D100 still open.

## State & architecture rules

- One Zustand store per open document: `{ doc, navStack, selection, viewportByDiagramId, ui }`.
- All mutations go through named actions (command pattern): `addNode`, `connect`, `convertSelectionToNested`, `remapPort`, … Each action produces an undo entry. No component mutates the doc directly.
- Undo/redo is document-global: undoing while viewing a child can affect the parent (e.g., undo "convert to nested"); in that case navigate the user to where the change happened.
- React Flow renders ONLY the current diagram (top of navStack). Nested node = custom node type `nested`; its collapsed preview is pure presentation from `collapsed` + `ports`.
- Stencils: each shape library section is a lazy-loaded module exporting `{ id, name, shapes: StencilDef[] }` where a StencilDef carries id, label, default size, and an SVG body. Cloud icon sets (Azure/AWS/GCP) use officially published icon packs (verify license, keep attribution file). Never inline thousands of stencils into the main bundle.
- Performance guardrails: memoized custom nodes, no store reads inside render loops, edge label measurement cached, target 60fps pan/zoom with 500 nodes on one canvas.

## Working agreements for Claude Code

- `PROGRESS.md` is the work queue: work strictly top to bottom within the current milestone, update statuses as you go, respect milestone exit tests. `CLAUDE_HISTORY.md` is the archive: completed items move there at milestone boundaries, and all decisions are logged there once with a "why". Read HISTORY only when past context is needed; never re-litigate its Decision Log.
- Before implementing any editor behavior, state in one line how draw.io does it; match that unless this file overrides it.
- Every model-layer change ships with unit tests, especially nesting invariants and the file format round-trip (`encode(decode(x)) === x`).
- No new dependencies without listing the reason in `PROGRESS.md` under the item that introduced them.
- Never break `.nedito` backward compatibility silently; breaking changes bump `formatVersion` and add a migration in `file/migrations/`.
- Commit style: conventional commits (`feat(canvas): edge waypoints`), small commits per work item.
- **Branch + PR workflow (from 2026-08-07, PR gate added same day): `main` is the protected, always-working MVP baseline — never commit directly to it, and never merge into it without the user's approval.** Every new work item (feature, fix, or user-requested change) gets its own short-lived branch off `main` (`feat/…`, `fix/…`). Before opening a PR: run the full verification sweep (`npm run test -- --run`, `npm run test:e2e`, `npm run lint`, `npx tsc -b`, `npm run build`) and confirm everything is green. Push the branch and open a PR with `gh pr create` describing what changed and the verification results — then stop and wait; do not merge it yourself even if checks pass. Only merge (`gh pr merge`) after the user explicitly approves in chat or approves the PR on GitHub. Resolve any `CLAUDE_HISTORY.md`/`PROGRESS.md` conflicts by renumbering the incoming Decision Log entry to the next free `D#` on `main`, never by dropping either side's entry. If a branch sits open while `main` moves on, don't let it go stale — flag it and get it merged or closed (this happened once with `feat/topbar-menus` sitting unmerged and caused real user-facing confusion: the feature looked "broken" because it simply wasn't on the branch being tested).
- **One PR open at a time (from 2026-08-10):** don't start the next branch/PR until the current one is merged. Stacking several open PRs in a row that all touch overlapping files (e.g. `store.ts`'s `ui` slice, `CLAUDE_HISTORY.md`'s decision log) caused a real cascade of merge conflicts — merging PR #5 out of order broke #3, then merging #3 broke #4, each requiring a full re-verify to fix. Serial delivery avoids this entirely. After a PR merges, pull `main`, delete the merged branch (local + remote), *then* branch for the next item.
- **Stacked PRs merge into their base BRANCH, not `main` (from 2026-08-20):** when PR B is opened against PR A's branch, merging A does not automatically make B target `main` unless GitHub's auto-retarget has already fired — and it does not fire if the two merges land seconds apart. B then merges into A's (often just-deleted) branch, shows a green MERGED badge, and contributes nothing to `main`. This happened with PRs #14 and #15: both reported MERGED, neither was in `main`, and it was only caught by the `git merge-base --is-ancestor` check below. Prefer avoiding stacks entirely (the one-PR-at-a-time rule exists for this reason); when a stack is genuinely unavoidable because two items rewrite the same code, merge them strictly one at a time and **verify each PR's base has retargeted to `main` before merging the next**.
- **After a PR merges, check for commits pushed after the merge (from 2026-08-10):** a PR can be merged by the user while a branch is still being actively pushed to (live-testing often surfaces one more fix mid-review). GitHub's merge only ever captures the branch's state *at the moment of merging* — anything pushed afterward silently sits on the (often auto-deleted) branch, invisible on `main`, with no error or warning from `git push`. This actually happened: PR #6 was merged after its first 2 commits, but 4 more were pushed in response to further live-testing reports before the merge was noticed, and none of those 4 landed on `main` — `git branch -d` correctly warned "not yet merged to HEAD" and it was misread as harmless squash-merge SHA noise. After every merge, run `git merge-base --is-ancestor <your-last-local-commit-sha> origin/main` (or read that branch-delete warning literally) before deleting a branch or moving on — don't assume "the PR shows MERGED" means "everything I pushed is in `main`."
- **Never write personal or machine-specific details into any file in the repository.** This covers `CLAUDE.md`, `PROGRESS.md`, `CLAUDE_HISTORY.md`, `README.md`, every file in `docs/`, code comments, commit messages, test fixtures and example documents. Specifically, never record: a person's name, email address or handle; a local filesystem path, Windows username or home directory (`C:\Users\<name>\...`); a machine name, IP address or local URL; the filename of a screen recording, screenshot or any other file sitting on someone's own computer; or anything that identifies whose machine the work was done on.
  Write about people by role instead. "The user", "the author", "a reviewer". When a decision came from a screen recording, a screenshot or a local file, say that it came from one and summarise what it showed, without naming the file or where it lives. `docs/about-copy.md` and `BRAND.contact` are the only places an address may appear, and only the product's own contact address.
  This applies to every surface that writes to this repository: Claude Code, Claude in the browser, and any other session. It is a review-blocking defect in the same class as hardcoding the product name outside `brand.ts`, and the reason is the same: this repository is public, so anything written here is published. `src/app/personalData.test.ts` guards it.
- All scripts, paths, and docs assume Windows/PowerShell.
